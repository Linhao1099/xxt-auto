# 学习通全自动任务机 · xxt-auto

> 一个 Tampermonkey 用户脚本。进到一个章节，把这一页的**视频、长图、章节测验**全做完，再自动去**下一个有任务点的小节**。

**这个项目的重点不是"能刷"，是"不漏"。**

刷课脚本满地都是，能跑通的不少，但挂一整夜回头一看、总有几个视频没播、几张长图没翻、几道题没答——这种事没人愿意一个个去对。所以这里花最多力气的地方是：**怎么确认一页真的做完了**，而不是怎么点得快。

- 视频台账按「小节 + 视频」记账，同一段视频挂在两节不再互相顶账
- 长图认得出还在懒加载的图（`naturalHeight` 是 0 也算）
- 测验页给双倍加载耐心，题卡上的"已作答"不会被误判成整卷已交
- 三类任务**并行推进**，谁有活谁干，任何一类卡住都不挡另外两类
- 都停了还要往下推 12 轮确认，把懒加载的东西逼出来才走

## 它能干什么

一个章节页里可能同时挂着好几种任务点。脚本会逐个啃：

| 任务类型 | 它做什么 | 怎么判定做完了 |
| --- | --- | --- |
| **视频** | 自动起播、1.5x、静音、播完接下一个（同页多个视频连着放） | `ended` 或剩余不足 1.8 秒，且翻遍整页没有再冒出新视频 |
| **长图** | 从上往下一格一格滚到底，慢慢滚，不一下跳到底 | 所有能滚的容器都到底，再留 2 秒给平台记账 |
| **章节测验** | 还原加密题干 → 问 AI → 自动勾选项 / 填输入框 → 自动点「暂存」 | 保存完停 1.5 秒就走（找不到暂存按钮也走） |
| **文档 / PPT** | 自动往下推着翻 | 推不动了就算完 |

三类都清干净了，才按左侧目录跳到**下一个有任务点的小节**。目录里没标记的小节会越过，但最多连跳 2 个——标记系统延迟更新时，第三个不管有没有标记都进去看一眼。

> **脚本永远不点「提交 / 交卷」。** 按钮文字里只要带「提交」或「交卷」，一律不碰。提交那一步永远留给你。

## 安装

### 1. 装 Tampermonkey

Firefox / Chrome / Edge 都行。装好扩展后确认它处于启用状态。

### 2. 装脚本

**方式 A（推荐）**：下载仓库里的 [`dist/xxt-auto.user.js`](dist/xxt-auto.user.js)，拖进浏览器窗口，Tampermonkey 会弹出安装页，点「安装」。

**方式 B（一键复制）**：用浏览器打开 [`dist/install.html`](dist/install.html)，点「复制脚本全文」，然后：

1. 点 Tampermonkey 图标 → 「管理面板」
2. 点左上角 `+` 新建脚本
3. 编辑器里 `Ctrl+A` 全选 → `Delete` 清空
4. `Ctrl+V` 粘贴 → `Ctrl+S` 保存
5. 回到学习通，**刷新页面**

### 3. 确认装上

刷新后右上角会出现一个深色面板，标题写着 `学习通全自动 v3.x`。

装不上就打开控制台（F12），看有没有以 `[xxt]` 开头的日志。

### 4. 自动更新

脚本头部已经指向这个仓库：

```
// @downloadURL  https://raw.githubusercontent.com/Linhao1099/xxt-auto/main/dist/xxt-auto.user.js
// @updateURL    https://raw.githubusercontent.com/Linhao1099/xxt-auto/main/dist/xxt-auto.user.js
```

所以只要仓库还在、分支还是 `main`，Tampermonkey 每次启动都会来问一句有没有新版。装过一次之后不用再手动粘贴。

> **Fork 之后**要换成自己的地址，重新构建一次：
>
> ```bash
> XXT_REPO=你的用户名/xxt-auto npm run build
> ```

## 用法

刷新页面后面板出现在右上角。

```
┌─ ● 学习通全自动 v3.3 ──────── [停止] [▸] [×]
│  章节：1.2 化学热力学
│  任务：视频 2/3 · 测验 12 题 · 已处理
├────────────────────────────────────
│  题目明文            ← 有测验时自动摊开
│  [1] 在一定温度下，发生变化的孤立体系…
│      A 不变
│      B 可能增大或减小
│  ...
│  答案：[D,B,A______] [填入] [问 AI] [暂存]
│  ☑自动问 AI ☑自动勾选 ☑自动暂存 ☑清完自动去下一节 ☐等交卷再走
│  答案已保存，准备去下一节
│  ▸ AI 设置
└────────────────────────────────────
```

### 五个开关

状态记在本机，下次打开还是你选的。

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 自动问 AI | 开 | 读到题目就自己问一次，不用点按钮 |
| 自动勾选 | 开 | AI 出答案后自动点选项 / 填输入框 |
| 自动暂存 | 开 | 全部填好后自动点页面上的「暂存 / 保存」 |
| 清完自动去下一节 | 开 | 这页任务全清完就跳下一节 |
| 等交卷再走 | **关** | 关＝保存完就跳；开＝停在原地等你点提交 |

### 控制台命令

面板装不上的时候，这些都是趁手的排查工具：

| 命令 | 作用 |
| --- | --- |
| `xxt.stop()` / `xxt.start()` | 停止 / 继续 |
| `xxt.next()` | 手动跳下一个有任务点的小节 |
| `xxt.tasks()` | **这一页还剩什么**：每个视频播到哪、有没有记账、几个长图盒、几道题 |
| `xxt.skipped()` | **跳过账**：哪一节、什么时间、为什么跳过 |
| `xxt.state()` | 当前状态：确认阶段第几轮、测验到哪一步、错误信息 |
| `xxt.storage()` | 配置存在哪、会不会丢 |
| `xxt.cfg()` | 现在存着的 AI 配置 |
| `xxt.rate(2)` | 改倍速（1–4），会记住 |

## 配置 AI（可选）

不配也能用——题目照样还原成明文，你自己填答案就行。配了才能全自动答题。

展开面板底部的「AI 设置」：

| 字段 | 例子 |
| --- | --- |
| 接口地址 | `https://api.deepseek.com/chat/completions` |
| 密钥 | `sk-...` |
| 模型名 | `deepseek-chat` |

填完点「保存设置」，再点「测试连接」当场验一下，通了会显示 `✓ 通了（deepseek-chat）`。

任何 OpenAI 兼容的 `chat/completions` 接口都行（Kimi、通义、本地 ollama 都算）。

**配置存在油猴扩展自己的存储里**，不在页面里。所以换子域、关浏览器、关机重启都还在。

<details>
<summary>为什么不用 localStorage（旧版的坑）</summary>

旧版把配置写在网页的 `localStorage` 里，它有三个躲不开的毛病：

1. **按域名隔离**：`mooc1.chaoxing.com` 和 `mooc2-ans.chaoxing.com` 是两个不同的 origin，这边填的到那边读不到
2. **会被清**：Firefox 的隐私设置、清站点数据、网站自己发的 `Clear-Site-Data` 都能把它带走
3. **关机就没了**：浏览器清会话数据时它跟着走

现在用 `GM_setValue` / `GM_getValue`，同时往页面存储写一份兜底。旧版本残留在页面里的配置会在第一次运行时自动搬过去。
</details>

## 工作原理

### 1. 加密题干怎么还原

学习通给题目套了一个自定义字体：真字的**码位不变**，但字形被随机打乱。所以页面上看到的是「在一定嵣度嵦，发嵥嵢化的嵡嵧嵤系」——文字本身是错的。

但是：**每个字的轮廓形状是固定的，而形状到真字的对应关系是全局唯一且不变的**。

所以流程是：

```
页面里 <style id="cxSecretStyle"> 的 @font-face 带着 base64 TTF
        ↓ 解 base64
解析 TTF：head / maxp / loca / glyf / cmap 五张表
        ↓ cmap 给出「码位 → 字形编号」
逐个字形读轮廓点：每个点的 x、y、是否在曲线上
        ↓ 按顺序拼成字符串（无分隔符）
MD5 → 取前 10 位十六进制 → 查表得真字
```

`dist/font-table.txt` 就是这张表：**73975 个字符 = 6725 条记录**，每条 11 个字符（10 位 MD5 前缀 + 1 个真字）。

两份实现都在仓库里：

- 浏览器端：`src/xxt-all.js` 里的 `md5hex` / `Reader` / `parseCmap` / `hashGlyph`
- Node 端：`tools/ttf-decode.mjs`，导出了同一套函数，可以脱离浏览器单独跑

> 有意思的地方：这套算法的关键在于"原始数据的码位被随机洗牌"。所以**硬编码任何映射都无效**——每次刷新页面字体都会换一份码位，必须现场从 TTF 算。这也是为什么字形表存的是"形状指纹"而不是"码位"。

### 2. 三类任务并行泵

早期版本是串行的：

```
视频 → 长图 → 测验 → 翻屏确认 → 跳
```

每一环都靠"这一轮什么都没发生"往下走。结果：视频起不来 → 长图轮不到；长图没认出 → 测验轮不到；测验在等 AI → 视频轮不到。**任何一环误判，整页就被当成做完了**——漏任务基本都是这么来的。

现在每一轮都问一遍三类：

```js
function pumpAll() {
  var busy = false;
  var v = pickVideo();  if (v) { playVideo(v); busy = true; }   // 视频静音后台播
  if (scrollLong()) busy = true;                                // 长图慢慢翻
  if (quizTick() === 'busy') busy = true;                       // 测验推状态机
  return { busy };
}
```

谁有活谁干，全都不忙才进入确认阶段。

### 3. 怎么确认"这页真的做完了"

```
三类都停了
   ↓
往下推一屏（整页 + 每个 overflow 容器 + iframe 里的）
   ↓ 立刻重扫
   冒出东西？→ 回去干活
   ↓ 没冒出来
推够 12 轮，或者哪里都推不动了
   ↓
再确认一遍 → 才跳下一节
```

### 4. 防漏的几个具体设计

| 场景 | 这里的处理 |
| --- | --- |
| 同一段视频挂在两节 | 台账键 = `小节名@页面路径 \| 地址哈希#时长`，两节两条账 |
| 视频还没加载出来（`src` 为空） | 认不出就返回 `null`，**绝不拿去记账**，老老实实等它加载 |
| 长图懒加载（`naturalHeight` 是 0） | 四重判定：`naturalHeight` / `height` / `getBoundingClientRect().height` / 宽高比 ≥ 2.5 |
| 视频缩在内部滚动容器里 | `scrollEverything()` 找所有 `overflow-y: auto/scroll` 的容器，包括 iframe 里的 |
| 测验页 iframe 加载慢 | 基础耐心 20 秒，URL 含 `work/quiz/exam/homework/test` 直接翻倍到 40 秒 |
| 题卡上有"已作答"字样 | 交卷判定只认「已提交 / 已交卷 / 提交成功 / 本次成绩 / 总得分」这几个硬信号 |
| 不同章节的测验都从 `data="1"` 开始 | 题目指纹 = `小节名 \| 题数 \| 第一题 id`，换节必然重新解析 |
| 目录标记延迟更新 | 最多连跳 2 个没标记的小节，第三个必进 |
| 视频拉不起来 | 同一个视频试 40 次就放弃，并记进「跳过账」 |

### 5. 「不提交」是怎么保证的

```js
var NAMES  = ['暂存', '暂时保存', '保存答案', '保存草稿', '保存'];
var DANGER = /提交|交卷|交答案/;

// 按钮文字精确等于 NAMES 之一，且不含 DANGER，才算暂存按钮
```

另外几层：

- 暂存按钮优先在**最后一题往上三层**的范围内找，找不到才回退整个文档——不会点到笔记、讨论区的「保存」
- 查找时排除脚本自己的面板（面板里也有个「暂存」按钮）
- 点了暂存如果弹出确认框，弹窗文案含「提交 / 交卷」就立即停手，什么都不点
- 测试里专门有一条断言：整轮流程下来，页面上那个「提交」按钮的点击次数必须是 **0**

## 排查

**面板没出现** → 确认地址是 `chaoxing.com` / `chaoxing.cn` / `edu.cn`，然后刷新。

**题目还是乱码** → 面板里应该已经是正常字了。仍是乱码就把那段文字截图提 issue。

**一直卡在某一页** → 敲 `xxt.state()`，它会写卡在哪一步；敲 `xxt.tasks()` 看它眼里的任务清单。

**怀疑漏了** → 敲 `xxt.skipped()`，每个被迫跳过的小节都有记录，带时间和原因。点回目录手动补一下。

**题目读出来但没有答案**（没配 AI）→ 等 3 分钟会自己跳过，不会整晚卡着。

**配置老丢** → 敲 `xxt.storage()`，看 `hasGM` 是不是 `true`。如果是 `false`，说明油猴没给存储权限，去 Tampermonkey 设置里检查。

## 开发

```bash
npm install          # 只装 jsdom，用来跑测试
npm run build        # src/xxt-all.js + dist/font-table.txt → dist/xxt-auto.user.js
npm test             # 两个测试套件
npm run check        # 只做语法检查
```

### 目录

```
src/xxt-all.js             全部逻辑（约 2500 行，单文件，无依赖）
build/build-all.mjs         注入字形表 → dist/xxt-auto.user.js
build/build-all-guide.mjs   生成 dist/install.html 安装页
tests/all.mjs               12 个场景 / 63 项断言（调度、防漏、存储）
tests/decode.mjs            36 项断言（MD5、字形还原、答案解析、不提交）
tools/ttf-decode.mjs        Node 版 TTF 解析器，可独立使用
tools/build-font-table.mjs  从 TTF 重新生成 dist/font-table.txt
tools/recover-all-src.mjs   从 dist 产物反向还原源码
tools/font-export.user.js   油猴脚本：导出页面里的加密字体
dist/font-table.txt         字形表（构建输入）
```

源码刻意保持**单文件、ES5 语法、零依赖**：粘进 Tampermonkey 就能跑，不用打包器，也不吃 CSP 的亏。

### 测试怎么跑的

`tests/all.mjs` 用 jsdom 造页面，把源码 `eval` 进去，然后断言行为。12 个场景：

| 场景 | 验证 |
| --- | --- |
| A 纯视频 | 起播、倍速、静音、播完切下一节 |
| B 纯测验 | 自动勾选 → 暂存 → 不等交卷就跳 |
| C 混排 | 视频先播完，再处理测验 |
| D 目录 | 越过没标记的小节 |
| E 只有提交按钮 | 存不上也先跳，提交点击 0 次 |
| F 等交卷再走 | 勾上后停在原地 |
| G 长图懒加载 | `naturalHeight` 为 0 也能认出并滚到底 |
| H 题目姗姗来迟 | 2.5 秒后才渲染的题，不许当空页面跳走 |
| I 「已作答」 | 不许误判成整卷已交 |
| J 两节同一视频 | 台账键必须带小节名 |
| K 配置持久化 | 旧数据迁移 + 「重启」后还在 |
| L 跨子域 | 在 mooc1 存的，mooc2-ans 也认 |

`tests/decode.mjs` 需要一份真实加密字体才能跑，没有就自动跳过（字形表已随仓库发布，日常不需要）。

### 重新生成字形表

只有当学习通换了绘制方式时才需要：

```bash

# 2. 存成 tests/fixtures/cxsecret.ttf

```

## 已知限制

- **只在 Firefox 实测过**。代码没用什么 Firefox 独有的东西，Chrome / Edge 理论上一样，但没验证。
- **字形表覆盖 6725 个常用汉字**。生僻字解不出来会保留原样，不影响做题（题干里的生僻字很少）。
- **长图必须是真的能滚**。如果平台改成"播放动画"来记录阅读进度，这套逻辑就不适用了。
- **题目分页时不处理**。学习通有些作业分「单页 / 分页」两种展示，分页模式下脚本只处理当前页的题。
- **AI 答案的准确率取决于模型**。脚本只负责搬运，对不对得你自己判断——尤其是有填空、简答的卷子。
- **不点提交是硬编码的**。想全自动交卷的话这个项目帮不了你，也不打算做。
